# Translations (i18n)

Every text a person can see or hear in MkFont 2 comes from a catalog: labels, menus,
tooltips, placeholders, accessible names and descriptions, dialogs, toasts, errors,
empty states, status lines, history entries and the main process's native menus and
dialogs. The app ships English (the source and the fallback), French, Spanish and
Simplified Chinese (`en`, `fr`, `es`, `zh`).

The language is a preference (Preferences → Appearance → Language): *System* by default,
the first of the system's languages (`navigator.languages`) the app ships, else English.
The renderer applies it before the first render and tells the main process
(`app:setLanguage`), which rebuilds its native menu; until then the main process uses
`app.getLocale()`.

## Choice: i18next + react-i18next

- **Maintained and standard.** i18next is the most used JavaScript i18n library, with
  frequent releases, and works the same in the renderer, in non-React modules and in
  Electron's main process (one instance each).
- **Typed keys and values.** The English catalogs are TypeScript objects (`as const`),
  so `t('browse.title')` is checked against them, a typo fails the typecheck, and a
  wrong interpolation name (`t('browse.noBlockMatch', { filtr })`) fails too.
  (A missing value is not caught: i18next treats values as optional.)
- **Plurals through `Intl.PluralRules`**: `key_one` / `key_other` (and `_few`, `_many`…
  per language) picked by `count`. The JSON v4 layout is what Weblate, Crowdin and
  Lokalise read, so a translation can start from an export of these objects.
- **Numbers through `Intl.NumberFormat` in the app's language**: `{{count, number}}` in a
  message, `formatNumber(n)` in code (not `toLocaleString()`, which follows the system);
  times of day with `formatTime()`.
- **No extra renders.** Catalogs are bundled and the instance initialises synchronously,
  so nothing loads or suspends. `useTranslation()` re-renders only on a language change.
  `t` is a plain function call.

FormatJS (react-intl) was the other candidate: ICU syntax is richer (select, nested
plurals), but it needs an extraction/compile step for typed ids and its non-React API is
more ceremony. A home-made layer would have meant writing plural and format handling
that i18next already has. ICU can still be added later (`i18next-icu`) if a language
needs it.

## Where things are

| Path | What |
| --- | --- |
| `src/renderer/src/i18n/index.ts` | The instance, `t`, `tm`, `formatNumber`, `formatTime`, re-exports `useTranslation`, `Trans`. |
| `src/renderer/src/i18n/message.ts` | `msg()`, `Message`, `MessageError`: text from code that must not import the instance (core/). |
| `src/renderer/src/i18n/i18next.d.ts` | Typed keys (`CustomTypeOptions`). |
| `src/renderer/src/locales/en/<area>.ts` | English messages, one file per area, joined in `locales/en/index.ts`. |
| `src/renderer/src/locales/<lng>/<area>.ts` | The translations, same files, each `satisfies Catalog<typeof en>`. |
| `src/renderer/src/locales/catalog.ts` | `Catalog<T>`: a translation's shape (English keys; plural forms per language). |
| `src/renderer/src/lib/language.ts` | Applies the language preference (`useApplyLanguage`, `applyLanguage`). |
| `src/main/locales/<lng>.ts`, `src/main/i18n.ts` | The main process's own catalogs and instance. |
| `scripts/i18n-literals.ts` | The check for literals (`npm run check:i18n`; also a test). |

## Conventions

- **Keys** are `<area>.<name>` in camelCase, nested by feature: `inspector.components.add`.
  Name a message for what it says, not where it sits, when it is used in several places.
- **One sentence, one message.** Never build a sentence from pieces (`'Copied ' + n + ' glyphs'`):
  word order differs between languages. Put the whole sentence in the catalog with
  `{{values}}`.
- **Plurals**: `pairs_one: '{{count, number}} pair'`, `pairs_other: '{{count, number}} pairs'`,
  called as `t('x.pairs', { count })`. Every plural has an `_other` form.
- **Markup inside a sentence** (`<span class="text-fg">3</span> glyphs`): `<Trans>` with named
  tags, `glyphs: '<n>{{count, number}}</n> glyphs'` and
  `<Trans i18nKey="x.glyphs" values={{ count }} components={{ n: <span className="text-fg" /> }} />`.
- **In components**: `const { t } = useTranslation()`.
- **Outside React** (commands, menus, toasts, stores) and in components drawn in large
  numbers (grid slots): `import { t } from '…/i18n'`, called when the text is shown. Never
  at module load: a constant built at import time would not follow the language.
- **Lists and registries** (commands, select options) hold ids or keys; the label is
  looked up when shown. Commands keep a `label` getter (`commands.<id>` in the catalog).
- **core/** has no access to the instance: it returns `Message` values (`msg(key, values)`)
  or throws `MessageError`; the UI shows them with `tm(m)` / `errorMessage(e)`.
- **Accessible names count as much as visible text**: `aria-label`, `aria-description`,
  `aria-valuetext` and screen-reader-only text are translated with the same wording.
- **English stays as it was**, typographic quotes, ellipses and non-breaking spaces included.
- **An intentional literal** (a brand name, a code, sample glyphs) takes an
  `// i18n-ignore: <reason>` comment on its line or the line above.

## Not translated

- **Unicode data**: character names and block names, from `core/unicode*`. They come from
  the Unicode Character Database, where the English name is the identifier. *Edge*: block
  names are shown as UI labels; translated names exist (CLDR has some) and could be added
  later as a separate catalog. General category names are translated (`unicode.categories`,
  `unicode.categoryGroups`, read through `lib/category-names.ts`): the two-letter code
  (`Lu`) is the identifier and stays beside the name.
- **File format keys and font data**: `.mkfont` keys, default family / style names written
  into fonts ("Regular"), SVG markup.
- **Log and debug text**, thrown errors that never reach the screen, test strings.
- **Key names in shortcut specs** (`Ctrl+Shift+S`) are matched, not shown; their display
  form is translated where it is formatted.

## The check

`npm run check:i18n` (and `src/renderer/src/__tests__/i18n.test.ts`) parses the renderer and
main sources and flags JSX text, text-like literals in text attributes and props
(`aria-label`, `title`, `placeholder`, `tip`, `label`…), in text properties of object
literals, in toast / dialog calls, and any other literal that reads as words. "Reads as
words": a letter, and a space, a capital or ending punctuation; ids, class lists, markup,
CSS and path data pass.

A template literal that puts a word beside a value with a space between (`${n} glyphs`)
counts as text too.

## Edges

- **History entries** are stored as text when the edit is made: after a language change,
  past entries keep the language they were made in.
- **The preview's sample sentence** is stored as `null` until the user types their own, so
  it follows the language. A text saved before this change keeps its English sentence.
- **Text from elsewhere** stays in its own language inside our messages: `JSON.parse`
  errors in "Not a valid .mkfont file (…)", opentype.js errors, operating system errors
  from the main process.
- **Generated files**: the Illustrator artboard script (comments, layer names) is file
  content, not UI.
- **Shortcuts written into a few tips** ("Glyph cell size (Ctrl+wheel on the grid)",
  some Preferences tips) are part of the message, as before, and do not follow macOS's
  ⌘ notation; command tooltips use `commandTip()`, which does.

## Translations

- **Plural forms** are the language's own, from `Intl.PluralRules`: French and Spanish
  have `_one`, `_many` (millions) and `_other` (in French 0 is `_one`); Chinese has only
  `_other`. A missing form would fall back to English, so the test requires all of them.
- **Typography** is the language's: French « guillemets » and a narrow no-break space before
  `: ; ! ?`; Spanish «comillas»; Chinese full-width punctuation and a space between Chinese
  and Latin text or numbers.
- **The preview's default text** is a pangram in French and Spanish; Chinese has none, and
  fonts made here are mostly Latin, so it keeps the English one.
- **Key names** in shortcuts follow the system's keyboard labels (French `Maj`, Spanish
  `Mayús`; Chinese keeps the English names).

## Adding a language

1. Copy `locales/en` to `locales/<lng>` (and `src/main/locales/en.ts` to `<lng>.ts`) and
   translate the values; each file ends in `satisfies Catalog<typeof en>`, so a missing or
   misspelled key fails the typecheck. Keep the `{{values}}` and the `<tags>`, and write the
   plural forms the language needs.
2. Add it to `LANGUAGES`, `LANGUAGE_NAMES`, `HTML_LANG` and `resources` in `i18n/index.ts`,
   to `LANGUAGES` and `resources` in `src/main/i18n.ts`, and to the list in the i18n test,
   which checks keys, values, tags and plural forms against English.
